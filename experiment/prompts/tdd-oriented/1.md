We are building the product page described in `REQUIREMENTS.md` with Test-Driven Development (TDD). TDD works in cycles of three phases: **Red** (write tests that describe the desired behavior; they fail because the feature is not built yet), **Green** (write the implementation that makes those tests pass) and **Refactor** (clean up while keeping the tests green).

**You are in the Red phase.** Your job is to write the tests. The implementation will be written afterwards, in the Green phase, using your tests as its specification, so the tests need to capture every expected behavior.

1. Set up the app with only what is needed to run the tests: an empty page, no features.
2. Write Playwright end-to-end tests that cover every requirement in `REQUIREMENTS.md`.

   The tests must follow and respect the WCAG 2.2 AA success criteria and the WAI-ARIA Authoring Practices Guide (APG) pattern of every component, including its roles, states, keyboard interaction and focus management.

3. Run the tests and confirm they fail because the features are missing, not because of syntax or configuration errors.
